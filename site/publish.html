Publish a theme

Public GitHub repositoryCurated listing

Publish the theme in its own public GitHub repository, make sure it installs with Omarchy's official command, then propose that repository for the curated registry.

Before submitting

  • A root colors.toml defines a complete, valid Omarchy palette.
  • At least one usable image lives directly under backgrounds/.
  • A root preview.png, .jpg, .jpeg, or .webp clearly shows the desktop.
  • The README includes installation, screenshots, credits, and known limitations.
  • A license file covers the theme and identifies separately licensed or restricted assets.
  • A clean omarchy theme install <repository-url> succeeds on current Omarchy.
  • You own or have permission to submit the theme and every included marketplace asset.

Submit the repository

Structured theme submission automation is the next implementation phase. For now, follow the repository contract and open an ordinary issue with the repository URL, theme name, author, short description, tags, tested Omarchy version, and completed rights checklist.

Review and publication

A maintainer checks the repository contract, current install behavior, listing metadata, and asset rights before adding the source to the registry. The publication build resolves an exact commit, generates previews and catalog data, runs tests, and requires review of the complete generated diff.

What curation means

The marketplace reads repository structure and theme data at one exact commit without executing repository contents. Listing is not a security review, endorsement, rights guarantee, or promise that future upstream remains unchanged. The normal install command obtains current mutable upstream.
